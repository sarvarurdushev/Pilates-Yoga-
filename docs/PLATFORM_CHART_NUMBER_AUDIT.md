## Follow-up: archived progress authority

`progress_evidence.py` now reads per-metric/signal status and model support from the saved report, checks the index's exact value/unit/time/client/source/demo identity, and requires an unambiguous suitable selected person. New publication uses the same selector. Old index rows are not rewritten. Missing-only legacy movement confidence can be recalculated with the existing analysis formula: mean of minimum contributing joint scores at every accepted source timestamp. Every required frame must be present, unique, suitable and supported; an explicit missing/low confidence is never replaced by person-level confidence or a constant.

Progress, body-region histories and program histories share this gate. Distinct evidence statuses and selected capture-local person IDs form distinct histories. Duplicate index entries from one assessment cannot create a fabricated second capture. Source report links remain the authority for original media and all technical evidence. A person's capture-local track ID does not prove identity across visits; the saved client relationship and reviewed capture supply that context.

Focused evidence and source-review regressions passed, alongside the chart/report/program history regressions. Full browser/role acceptance and live durable-storage deployment are still separate gates; this follow-up does not claim the entire specification is complete.
