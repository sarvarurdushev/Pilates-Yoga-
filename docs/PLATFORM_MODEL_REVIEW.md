# Model and scan integration review

Reviewed September 22, 2026. This supplements MODEL_EVALUATION.md. The deployment target is the existing CPU-only Render service with 512 MB RAM. Measurements are coaching observations, never radiological diagnoses.

| Technology | License / compatibility | Accuracy boundary and decision |
|---|---|---|
| RTMO through rtmlib / ONNX Runtime | Apache-2.0 model/framework components; existing CPU inference | Retain actual multi-person 2D keypoints, visibility checks and tracking. Anatomical side follows model joint IDs. Occlusion, projection and identity errors require coach review. [Primary project](https://github.com/open-mmlab/mmpose/tree/main/projects/rtmo). |
| MediaPipe Pose Landmarker | Apache-2.0 framework; installed 0.10.32, CPU-capable | Integrated independent estimated 3D coordinates, admitted only when visible joints agree with 2D. Hip-relative world coordinates are model estimates, not a calibrated scan. No invented depth for rejected frames. [Official documentation](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker). |
| Existing BodyParts3D atlas / Three.js | Keep existing asset attribution and licenses; browser rendering | Integrated actual structure IDs, anatomical side, educational layers, client notes and scan/analysis links. This reference atlas is not reconstructed patient anatomy. A browser with working WebGL is required; failure retains contextual links and instructions. |
| pydicom 3.0.2 | MIT, NumPy already installed, no neural weights | Integrated actual DICOM pixel decoding, rescale, grayscale windowing, inversion and frame selection; manual markers carry frame and region IDs. Supports uncompressed, RLE and baseline JPEG when decoder permits. Other compression returns a conversion instruction. No segmentation or disease inference. [Primary repository and decoder requirements](https://github.com/pydicom/pydicom). |
| Cornerstone3D | MIT, JavaScript/WebGL/WASM | Suitable for advanced volume/DICOMweb clients, but introduces another renderer and deployment bundle. Current requirements use server-decoded 2D images and SVG annotations, including on clients without WebGL. Evaluated; not installed. [Primary repository](https://github.com/cornerstonejs/cornerstone3D). |
| SMPL | Model downloads require registration and model license; commercial licensing separately offered | Body-surface fitting cannot identify internal bones or turn a photograph into an X-ray. No model assets redistributed under an assumed software license. Existing corroborated pose coordinates and licensed reference atlas provide the applicable functionality. [Model and licensing site](https://smpl.is.tue.mpg.de/). |
| TotalSegmentator | Apache-2.0 main CT/MR tasks; additional tasks have different terms; requires PyTorch 2+ | Segments volumetric CT/MR, not a single ordinary photo or projected X-ray. Its model/volume footprint is unsuitable for this 512 MB target. Not installed; no UI claims segmentation. Uploaded frames remain viewable and annotatable. [Primary implementation, tasks, requirements and validation paper](https://github.com/wasserth/TotalSegmentator). |
| Stanford CheXagent-8b | Hugging Face model card uses Transformers, custom code, CUDA and float16. A redistributable commercial model license was not established from the reviewed card. | Chest-X-ray interpretation is outside posture coaching. Eight-billion-parameter inference cannot fit this service; paper performance does not establish clinical safety here. Not downloaded, executed or presented as a diagnostic feature. [Primary model card](https://huggingface.co/StanfordAIMI/CheXagent-8b/blob/main/README.md). |

## Verification

`tests/test_platform.py` verifies valid DICOM decode/window output, invalid compression/frame rejection, protected media and stored annotations. The browser upload test used an explicitly named two-frame grayscale calibration pattern, not a fabricated medical image. Licensed public radiographs are matched by region, attributed in the viewer, and marked as educational references rather than the fictional client's scans.

Real video verification produced 34 tracked frames for the selected person and five accepted 3D frames; missing depth remained unavailable. Those figures validate this fixture, not accuracy on arbitrary users. Browser WebGL rendering and hosted inference must be recorded separately in the completion checklist.
